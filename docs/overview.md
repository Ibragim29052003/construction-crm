# Как работает система

В системе два типа пользователей. Постановщик видит все стройки, создаёт объекты и задачи, назначает исполнителей. Исполнитель видит только свои задачи и те объекты, где у него есть работа. На общем объекте задачи других сотрудников ему не показываются.

Путь задачи простой: новая → в работе → на проверке. Исполнитель берёт работу и сообщает о готовности. Постановщик проверяет результат и либо принимает его, либо возвращает с обязательным пояснением. После исправлений исполнитель снова берёт задачу в работу и отправляет на проверку. Самостоятельно принять собственную работу он не может.

В карточке задачи остаётся история: кто и когда изменил статус, что было до этого и какой комментарий оставил. Она сохраняется одновременно со сменой статуса: ситуация «статус изменился, а история потерялась» не возникает. Отредактировать или стереть запись истории через приложение нельзя. Даже удаление задачи сохраняет журнал в базе: из рабочих списков задача просто исчезает.

Защита работает в самой базе данных. Даже если исполнитель попробует отправить запрос в обход страницы, база не отдаст чужие задачи и не разрешит запрещённое действие. Пользователь не может назначить себе роль руководителя. Новых сотрудников добавляет администратор; самостоятельная регистрация закрыта.

Если связь оборвалась, повторное создание или повторная отправка одного изменения статуса не создаёт копий. Если два сотрудника одновременно меняют одну задачу, второй получит сообщение о конфликте и сможет обновить данные — чужие изменения не будут молча затёрты.

Для проверки можно войти постановщиком и двумя исполнителями, сравнить доступные объекты и пройти весь цикл одной задачи. В демонстрационной базе три объекта и задачи во всех пяти статусах.
